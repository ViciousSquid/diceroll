# diceroll test suite

Run from the repository root using **only Python's standard library**:

```sh
python -m unittest discover -s tests -v
```

All test files exercise the **real exported package**: no mocked dice
functions, hand-fabricated roll results, copied SVG assets, or replacement
rendering code.

| File | Coverage |
| --- | --- |
| `test_diceroll.py` | Original parser, roll, history, probability and SVG regressions |
| `test_real_rolls.py` | Literal golden outcomes for known seeds; standard/nonstandard dice; signed mixed totals; advantage/disadvantage; fixed and mixed random d6 colours; actual successes/failures |
| `test_probability_exhaustive.py` | Independently enumerated probability oracle, all six standard die types, signed/shifted distributions, reproducible sampling, check thresholds and safety limits |
| `test_svg_assets.py` | Real bundled PNG/JPEG signatures; all 18 d6 face/colour combinations; MiniWind d4/d8/d10/d12/d20 assets; full base64 decode and comparison to shipped bytes; vector fallback; SVG layout and target text |
| `test_headless_persistence.py` | Fresh isolated Python subprocesses with GUI imports forbidden, SVG without a window, JSON colour/history round-trips, immutable results and subscriber isolation |
| `test_pygame_animation.py` | Optional real pygame-ce surfaces: independently timed motion, exact settled faces/colours, repeatable pixel output, auto-detection, renderer boundary and no window ownership |

## Golden RNG fixtures

Some tests assert **exact**, hard-coded results from `random.Random(seed)`
(e.g. seed 0 gives `d4+d6+d8+d10+d12+d20` faces
`(4,4,1,5,9,16)`, total `39`). These are intentional contract tests:
a regression in dice iteration or RNG consumption must not silently pass
just because it also changed the expected-value calculation.

Other tests use independent exhaustive enumeration of all faces for small
mixed expressions, not a second call to the production probability routine.

For SVG images, tests decode the `data:` URIs generated by the real
renderer and compare their **original bytes** with assets installed in
the Python package. The d6 suite covers every face 1 through 6 in
red, white and blue, plus `d6_colour="random"` across individual
dice within the same roll.

## GitHub Actions

`.github/workflows/tests.yml` runs the complete suite on Python
3.10, 3.12 and 3.14 on Linux, plus **Linux, macOS and Windows** on
Python 3.12. It builds the wheel and source distribution, installs
them, and runs a separate `python -I` headless smoke test against the
installed module. Three additional native Linux/macOS/Windows jobs install
**optional** `pygame-ce` and exercise the real animation against offscreen
Pygame surfaces. The installed package must declare **zero runtime
dependencies** and may not import Pygame or Qt merely by importing `diceroll`.

Subprocess headless tests disable GUI display access and prohibit
importing `pygame`, `PyQt5`, `PIL`, `tkinter` and `PySide6`.
The tests never require a display server, audio device or GPU. Optional
Pygame rendering initialises its own font subsystem while running offscreen.

## Extending tests

Use a literal known-good seeded result when checking exact roll behaviour;
add a new independent oracle rather than repeating the implementation.
Exercise both the returned `RollResult` and external effects (events,
history, JSON or SVG bytes). Avoid probabilistic pass/fail assertions
whose outcome changes on each run.
